# Kanban: обзор и метрики

## Что такое Kanban

Kanban — метод управления потоком работы, основанный на визуализации задач и ограничении объёма незавершённой работы (Work In Progress, WIP). В отличие от Scrum, Kanban не предписывает фиксированные итерации (спринты) — работа течёт непрерывно.

## Канбан-доска

Доска со столбцами, отражающими этапы рабочего процесса, например: `To Do → In Progress → Code Review → Testing → Done`. Каждая задача представлена карточкой, которая перемещается по столбцам по мере выполнения.

## Базовые принципы Kanban

1. Визуализируйте рабочий процесс.
2. Ограничивайте объём незавершённой работы (WIP limits).
3. Управляйте потоком (Flow).
4. Делайте политики процесса явными.
5. Используйте обратную связь (петли обратной связи).
6. Улучшайтесь совместно, эволюционно (через эксперименты).

## Ключевые метрики потока

- **Lead Time** — время от момента создания задачи (или попадания в очередь) до её завершения.
- **Cycle Time** — время от начала активной работы над задачей до её завершения. Обычно меньше Lead Time.
- **Throughput** — количество задач, завершённых за единицу времени (например, за неделю).
- **WIP (Work In Progress)** — количество задач, находящихся в работе одновременно. Ограничение WIP помогает снизить переключение контекста и ускорить Cycle Time (закон Литтла: Lead Time = WIP / Throughput).
- **Cumulative Flow Diagram (CFD)** — диаграмма, показывающая количество задач в каждом статусе во времени; помогает выявлять "бутылочные горлышки".

## Kanban vs Scrum

| | Scrum | Kanban |
|---|---|---|
| Итерации | Фиксированные спринты (1-4 недели) | Непрерывный поток |
| Роли | Product Owner, Scrum Master, Developers | Не предписаны |
| Планирование | Sprint Planning перед каждым спринтом | Постоянное пополнение очереди (backlog refinement) |
| Ограничение работы | Через объём спринта | Через явные WIP-лимиты на столбцах |
| Метрики | Velocity (объём story points за спринт) | Lead Time, Cycle Time, Throughput |

На практике многие команды используют гибридный подход — Scrumban — совмещая спринты Scrum с визуализацией и WIP-лимитами Kanban.
